# W3-D2 结论存档(2026-11-12,与 Claude 对话定稿)

> 本文是精读日对话结论的定格,属个人知识资产——阶段一总结笔记(W3-D5)的直接素材。

## 光谱的本质

- Workflow = 路径由开发者预定义;Agent = 模型在循环里动态决定路径
- 选型本质:**「路径确定性」与「适应泛化性」之间的交换**

## 确定性的精确含义

- Workflow 的错误 = **可复现的 bug**:同输入永远同错误,修一次永远好(md5 可验)
- Agent 的错误 = **概率性偏差**:这次对不代表下次对,只能统计,不能保证
- 所以本项目的两个动作各有对应:确定性靠 md5 对照实验(把一切变化字段——连时间戳——排除出输出);Agent 可靠性靠稳定性测试(10/10)+ 护栏单测(guardrails 6/6)

## 前瞻外包与护栏对价

- Workflow 的「前瞻性不足」= **预设路径之外即失效**;Agent 把「前瞻」外包给模型
- 代价是不确定性。护栏(预算/白名单/可观测)不是消除不确定,是**压到可接受区间**;评估(稳定性测试)把它框出来变成可度量
- 收束一句:**护栏与评估,是 Agent 为「泛化性」支付的对价**

## 对照实验证据(w3/d2/workflow-chain.ts)

| | Chain 版 | Agent 版(p1-cli) |
| --- | --- | --- |
| 耗时 | ~17ms | 30-90s(均值 46.8s) |
| 成本 | 0 token | ~1-3 万 tok / ¥0.02 |
| 确定性 | md5 逐字节相同 | 措辞漂移 |
| 换任务 | 改代码 | 改一句话 |

## 后续架构方向(本人提出,2026-11-12 → 停车场,W4+ 议题)

想法:把确定性的工作封装成 workflow(每个 workflow = 一个工具的 execute 内部实现),Agent 只负责「选择、串联、组合 workflow」完成开放式任务。

关键认知与代价,详见与 Claude 的对话记录;要点:
- FC 只是暴露机制,不变;变的是**工具粒度**(原子操作 → 完整流程)
- 四条代价:灵活性下沉(该灵活的做成参数)/ 错误归因要分层(选错流程 vs 流程内失败)/ 前瞻负担回移(新任务类型要先写 workflow)/ 选择负担(description 质量决定选错率)
- 独特收益:**测试策略分层**——workflow 内部可单测,agent 层只测「选对串对」,各自可验证
